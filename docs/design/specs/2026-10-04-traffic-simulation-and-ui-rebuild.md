# 交通仿真、车辆 AI 与 UI 重建规格

## 1. 目标

在保留当前机器学习实验链路的前提下，恢复并重构旧版项目中的交通仿真能力。新版主环境必须能够解释周围车辆为什么加速、减速、跟驰、变道或发生碰撞；UI 只负责渲染主环境状态，不再维护另一套独立运动逻辑。

本阶段不实现手动驾驶，也不训练强化学习模型。强化学习只要求保留清晰的环境和策略接口。

## 2. 参考与边界

实现依据按以下优先级排列：

1. 当前项目的稳定数据契约、奖励和评测接口；
2. 旧版 `legacy/pre_refactor/2_ai` 中的 UI、车辆资源和交通 AI；
3. 用户提供的 `同车行.../full.md` 中的车辆动力学、传感器区域、跟驰和变道原则。

旧版代码只作为行为参考，不能未经审核直接复制。远程 `main` 保持在 `368d02f`，所有实现先在本地完成和验收。

## 3. 统一仿真状态

每辆车必须包含以下状态：

- `vehicle_id`：稳定标识；
- `x`：纵向位置；
- `y` 或连续横向车道位置；
- `lane` 与 `target_lane`；
- `speed`、`desired_speed`、`acceleration`；
- `length`、`width`；
- `behavior_mode`；
- `is_changing_lane`、`is_crashed`。

自车和交通车使用同一套坐标、单位和时间步。车辆不会通过瞬移完成变道，变道必须有明确持续时间和横向轨迹。

## 4. 交通更新顺序

每个仿真步固定执行：

```text
感知 → 行为决策 → 纵向控制 → 横向控制 → 状态积分 → 碰撞检测 → 事件记录
```

交通车行为模式至少包括：

- `CRUISE`；
- `FOLLOW`；
- `BRAKE`；
- `PREPARE_LANE_CHANGE`；
- `LANE_CHANGE`；
- `LANE_CHANGE_ABORT`；
- `EMERGENCY_BRAKE`；
- `CRASHED`。

交通车需要支持期望速度、速度边界、加速度边界、跟驰距离、TTC 和相邻车道安全检查。驾驶风格通过参数配置区分 conservative、normal、aggressive，不复制三套逻辑。

## 5. 感知与碰撞

感知必须基于车辆几何范围和车道重叠，而不是只比较 sprite 左边缘。至少输出前中、前左、前右、后左、后右车辆的距离、相对速度、TTC 和占用状态。

碰撞检测需要区分：

- `ego_traffic`：自车与交通车；
- `traffic_traffic`：交通车之间；
- `rear_end`：纵向追尾；
- `side`：变道或横向碰撞；
- `obstacle`：与静态障碍物碰撞。

碰撞事件必须包含双方 ID、时间步、场景、车道、碰撞前间距、碰撞后间距、双方速度、TTC、行为模式和原因。

## 6. 诊断输出

每个 episode 支持输出逐步 JSONL 轨迹和最终汇总。逐步记录至少包含：

- 自车状态与动作；
- 所有交通车状态；
- 各车辆行为模式；
- 当前感知结果；
- 奖励分量；
- 碰撞、变道、超车和安全接管事件。

最终汇总包含碰撞次数、碰撞类型分布、碰撞原因分布、最大/最小 TTC、变道次数、超车次数、平均速度、存活步数和回报。

## 7. 策略接口

保持：

```python
policy.act(observation) -> Action
```

Rule、Neural、Hybrid 继续实现该接口。环境观察扩展后，现有策略通过适配层兼容；新算法不直接依赖 Pygame。

## 8. UI 重建

UI 迁移旧版布局和资源，但只读取当前环境状态。UI 必须显示：

- 三车道道路和车辆动画；
- 自车策略与动作；
- 每辆附近交通车的行为模式；
- 速度、车道、TTC、安全距离；
- 当前 episode 指标；
- 最近事件和碰撞原因。

UI 不实现独立的交通运动，不复制 `HighwayEnv` 的更新逻辑。Pygame 是可选展示层，不影响无界面训练和测试。

## 9. 测试验收

必须增加并通过：

- 车辆初始不重叠；
- 跟驰车辆不会穿透前车；
- 变道过程连续且可完成/中止；
- 交通车碰撞可检测并解释；
- 自车碰撞可检测并解释；
- 固定 seed 轨迹可复现；
- UI 与无 UI 使用同一环境状态；
- 原有数据、训练、评测和向量环境测试全部回归通过。

完成后先在本地运行完整验收和 UI 演示，由用户确认，再合并阶段性提交并同步 GitHub。
