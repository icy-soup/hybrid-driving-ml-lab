# 神经与规则混合型智驾项目：总目标、实施路线与当前状态

更新日期：2026-10-04

## 1. 项目最终目标

本项目的背景保持为学校正式题目中的多车高速公路智能驾驶场景，但最终产出不把自己限制成“只会做智能驾驶”。项目要展示的是一套可解释、可复现、可扩展的人工智能实验系统，重点体现：

- 多智能体交通仿真与状态建模
- 规则先验、监督学习、MPC 和强化学习的对照
- 物理约束与安全屏障
- 可审计的奖励、碰撞和行为日志
- GPU 训练能力与 CPU 可复现实验
- 能够写入简历和结项报告的工程化项目结构

智能驾驶是应用背景；简历表达重点应放在仿真建模、策略学习、评价设计、风险控制和实验工程上。

## 3. 正确的系统架构

```text
HighwayEnv（唯一状态推进者）
    ├── 车辆生成器：负责安全出生点、屏幕外进入、回收
    ├── TrafficWorld / TrafficDriver：负责非自车行为
    ├── Perception：负责几何感知、TTC、五区域
    ├── Ego Policy：Rule / MPC / Neural / DQN
    ├── Collision Events：负责参与者、类型、原因和快照
    ├── Reward & Evaluation：负责距离主分和安全惩罚
    └── UI Renderer：只读快照，不复制任何运动逻辑
```

必须遵守：

1. UI 不得自己更新车辆位置。
2. 交通车不得只由随机速度推进。
3. 车辆必须从道路几何允许的屏幕外位置生成，再进入视野。
4. 出生时必须检查同车道前后间距、横向冲突和自车安全窗。
5. 每步日志必须能还原车辆状态、行为模式、奖励和碰撞原因。
6. 强化学习只能训练 ego；交通车使用固定、可解释、可复现的行为模型。

## 4. 实施步骤

### 阶段 A：保留旧 UI 并冻结基准

- 读取旧 `Main.py`、`ai_module.py`、`enemy_ai_module.py`
- 记录旧坐标、参数、生成/回收条件和输入控制
- 用截图和固定种子保存基准行为
- 不删除旧代码，不把新 UI 当作替代品

### 阶段 B：重建可审计的环境状态

- `VehicleState` 增加连续横向位置、目标车道、尺寸、速度、加速度和行为模式
- 感知统一使用车头/车尾几何间距
- 明确前中、前左、前右、后左、后右五个区域
- 保留动作编号：

| 编号 | 动作 |
|---:|---|
| 0 | 加速 |
| 1 | 制动 |
| 2 | 左变道 |
| 3 | 右变道 |
| 4 | 巡航 |

### 阶段 C：交通车逻辑

- 交通车生成必须从屏幕外开始
- 生成必须拒绝不安全位置，而不是生成后再强行挤开
- 交通车具备巡航、跟车、制动、紧急制动、准备变道、变道和中止变道状态
- 车道内间距必须在积分前后都检查
- 交通车行为必须在日志中留下 `mode`、目标速度、目标车道和原因

### 阶段 D：评价与日志

- 主分以有效行驶距离和存活进度为主
- 碰撞为强惩罚
- TTC、舒适性和换道为小权重
- 超车只做低权重或统计项，不能成为随机交通下的捷径
- JSONL 每步至少记录：速度、距离、奖励分量、车辆列表、行为模式
- 碰撞事件至少记录：两车 ID、类型、步数、间距、相对速度、TTC 和原因

### 阶段 E：基线算法

按以下顺序比较：

1. RulePolicy
2. 离散短视 MPC
3. 行为克隆 NeuralPolicy
4. 行为克隆初始化的 DQN
5. DQN + Safety Shield

所有算法必须使用同一批固定 seed、同一场景集合和同一评价指标。

### 阶段 F：强化学习

- 先冻结环境、生成器、日志和评价指标
- 再进行 CPU smoke training
- 再使用 CUDA 进行正式 DQN 训练
- 只让 ego 学习，交通车策略固定
- 报告 Rule / MPC / BC / DQN / DQN+Shield 的距离、碰撞率、存活步数和安全分

## 6. 当前仍未完成、不能冒充完成的内容

### 6.1 车辆生成链路仍需重审

当前随机生成逻辑虽然有最小间距检查，但还没有完全按照旧版的“屏幕外生成 → 进入道路 → 超出边界回收”流程迁移。必须补充：

- 屏幕外出生位置测试
- 出生时与 ego 的前后安全窗测试
- 出生时与同车道车辆的几何间距测试
- 连续运行 600 步的生成/回收测试
- 不同 seed 下无初始碰撞测试

### 6.2 旧 UI 还没有完全等价迁移

当前 UI 已恢复旧尺寸、字体和部分素材，但车辆精灵选择、旧版控制面板细节和旧版交互仍需逐项比对。不能仅凭“能显示”就称为旧 UI 已恢复。

### 6.3 交通车行为覆盖不足

当前日志已出现 `FOLLOW`，但还要覆盖并验证：

- `BRAKE`
- `EMERGENCY_BRAKE`
- `PREPARE_LANE_CHANGE`
- 连续横向变道
- 被占用时中止变道
- 交通车之间的碰撞分类

### 6.4 分数仍需归一化

当前距离主分已经不再把负 reward 直接显示成 UI 主分，但不同场景的原始距离规模不同。强化学习正式实验前还需要增加 `0–100` 的归一化安全进度分，同时保留原始距离和 shaped reward 作为诊断量。

## 7. 当前验收标准

在用户验收前，至少必须满足：

1. 固定 seed 的初始车辆全部在道路允许区域内。
2. 前 100 步不出现无原因初始碰撞。
3. 连续 600 步中车辆生成、进入、运动、回收链路不破坏车道几何。
4. 日志能看到至少一次 `FOLLOW`、一次 `BRAKE` 或紧急制动、一次换道决策。
5. UI 显示的车辆位置与 headless JSONL 同步。
6. UI 主分非负，距离和 reward 分开显示。
7. 全量测试通过。
8. 用户确认旧 UI 的道路位置、车辆资源和控制面板符合预期。

## 10. 分阶段测试计划

### T0：静态与接口检查

目的：确认代码结构没有把旧 UI、环境和策略接口混在一起。

检查项：

- `compileall` 通过
- 动作编号仍为 `0,1,2,3,4`
- `HighwayEnv.reset/step/observe` 接口兼容
- UI 渲染函数不修改环境对象
- 旧 UI 资源路径全部存在
- 当前提交不包含未审核的实验 UI

通过条件：所有检查通过，且没有依赖隐藏的全局坐标或随机状态。

### T1：初始生成测试

每个 seed、每个场景都必须检查：

- 自车初始位置固定且位于中间车道
- 交通车初始 `x` 位于屏幕外或明确的道路可视范围
- 交通车初始 `lane` 只在 `0,1,2`
- 交通车初始 y 必须等于旧 UI 的 `200,250,300` 车道中心
- 自车与交通车无初始几何重叠
- 同车道前后间距不小于安全间距
- 交通车不会出生在自车碰撞区域内

最低覆盖：`empty`、`slow_lead`、`sudden_brake`、`obstacle`、`rear_approach`、`random`、`mixed`，seed 至少 `0–99`。

### T2：屏幕外进入与回收测试

连续运行至少 600 步，记录每辆车的生命周期：

```text
spawn_outside → enter_road → stay_in_lane → leave_screen → removed
```

必须检查：

- 车辆从屏幕外进入，而不是突然出现在自车旁边
- 进入过程中车道中心保持正确
- 离开道路后被回收，不继续无限增长
- 回收不会改变其他车辆的位置
- 车辆数量不会无限增长
- 每辆车都有唯一 ID

### T3：车辆运动与交通 AI 测试

对每辆交通车记录：

- `x/y/lane`
- 速度和加速度
- `target_lane`
- `mode`
- 决策原因

必须分别触发并验证：

- `CRUISE`
- `FOLLOW`
- `BRAKE`
- `EMERGENCY_BRAKE`
- `PREPARE_LANE_CHANGE`
- `LANE_CHANGE`
- `LANE_CHANGE_ABORT`
- `CRASHED`

长序列约束：

- 无车辆横向跳跃
- 无车辆瞬移到其他车道
- 无车辆穿透同车道前车
- 速度变化受最大加速度和减速度限制
- 交通车不会因为 UI 刷新而改变状态

### T4：碰撞测试

必须使用确定性几何夹具，而不是只依赖随机场景：

1. 车头与车尾刚好接触：不应误报或漏报。
2. 同车道前后重叠：分类为 `rear_end`。
3. 横向重叠：分类为 `side`。
4. ego 与交通车碰撞：记录 ego ID 和交通车 ID。
5. 交通车与交通车碰撞：记录双方 ID。
6. 碰撞前一步和碰撞当步都要写入日志。

每个事件必须包含：步数、场景、车道、间距、相对速度、TTC、行为模式和原因。

### T5：UI 映射测试

旧 UI 左侧单独验证：

- 环境 lane `0/1/2` 映射到旧 UI 的 `200/250/300`
- 环境 `x=0` 映射到旧 UI 自车锚点
- `x<0` 的车辆从左侧进入
- `x>road_width` 的车辆从右侧离开
- 车辆精灵由车辆类型/ID 稳定选择，不是所有车使用同一张图片
- 碰撞车辆使用旧爆炸素材
- 变道过程使用连续 y，而不是直接跳 lane

右侧面板验证：

- 主分、shaped reward、距离分开显示
- TTC、行为模式、碰撞原因来自同一份环境快照
- UI 不推进环境、不生成新车辆、不改变车辆速度

### T6：评分与日志测试

每个 episode 必须同时输出：

- 原始距离
- 归一化安全进度分
- shaped reward
- 碰撞惩罚
- TTC 警告
- 换道次数
- 超车次数（只统计，不作为主导奖励）

异常检查：

- 没有碰撞时主分不得为负
- 相同 seed、相同策略必须得到相同结果
- 日志 JSONL 每行都能被 `json.loads` 读取
- 日志中不能出现 NaN 或 Infinity
- 发生碰撞时必须能从日志定位原因

### T7：基线与强化学习测试

在正式训练前固定：

- 场景集合
- seed 集合
- episode 步数
- 评分定义
- 诊断字段

先运行：

```text
RulePolicy
MPCPolicy
NeuralPolicy
BC-initialized DQN
DQN + SafetyShield
```

每个策略至少报告：平均距离、平均安全分、碰撞率、平均存活步数、最小 TTC、换道数。

## 11. 当前问题清单

- P0：会导致车辆一开始碰撞、跑出道路或无法运行，必须立即修复

- P2：不影响仿真正确性，但影响展示或实验质量
